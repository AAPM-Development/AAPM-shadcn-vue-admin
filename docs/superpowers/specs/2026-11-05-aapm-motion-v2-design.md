# AAPM Motion & Interaction v2 — design

Status: approved in chat section by section (2026-11-05) · Sub-project **A** of 2 (B = ERP component completeness, separate spec)

## Goal

Every interaction in the AAPM admin gives deliberate, smooth, light feedback — down to the typing
caret and the meaning of each action icon — without touching `components/ui` primitives and while
honouring `prefers-reduced-motion`.

## Decisions (from the user)

| Topic        | Decision                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| Order        | A (motion foundation) before B (ERP components), so B inherits A                                     |
| Engine       | motion-v (already a dependency) + CSS + small composables. No GSAP, no new runtime dependency        |
| Smooth caret | All single-line fields (text, number, email, password, search, OTP). Textarea keeps the native caret |
| Toast colour | Solid only for blocking (error). Success, info and warning stay pastel with colour accents           |

## Constraints

- `components/ui/**` stays stock; behaviour attaches through `data-slot` / `data-state`, tokens, plugins and AAPM components.
- Motion: ≤ 420ms per interaction; transform / opacity / scale / rotate only, except `AutoHeight` and collapsible height (reka height variables).
- All motion behind `prefers-reduced-motion: no-preference`. The blocked sound still plays under reduced motion.
- Directional motion blur only on dialogs, menus, toasts and the blocked shake (already shipped).
- Bahasa Indonesia copy; light and dark themes; ERP UX-08 contrast (text ≥ 4.5:1, UI boundaries ≥ 3:1).

## Accessibility and performance

- The overlay caret is decorative (`aria-hidden`); the native caret stays for assistive tech and IME.
- Solid blocking toast text ≥ 4.5:1 on its red; icons and labels carry meaning, never colour alone.
- No `scroll` listeners; caret measurement uses a hidden mirror span re-used per input and one rAF per event.
- Icon animations run on hover/press only, never on page load in bulk.

## Testing

- Vitest (TDD) for `measureCaret`, `useStagedList` (phase order, rapid changes, no ghosts), `AnimatedIcon` (every action has keyframes and an accessible name), toast wrappers (type → class / icon / sound).
- `motion-coverage.test.ts` extended: every action icon in the registry has an animated variant; every toast type has a style.
- Manual / browser: each interaction in `/ui-kit`, layout auditor at 375 and 1280 in light and dark, lint + build + test green.

## Non-goals

ERP component completeness (sub-project B), textarea smooth caret, GSAP, new audio files, changes to `components/ui`.

## Addendum — full scope (2026-11-05)

The user asked that "full scope" cover every surface: categorical status and chip colour for quick scanning, immersive animated dropdowns, select-type pickers, and data visualizations. Constraints above still apply. One exception: chart entrance may run up to 900ms, which the existing sparkline and bar-list already do.
